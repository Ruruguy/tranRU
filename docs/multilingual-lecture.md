# 演講多語互譯與雙向溝通排版 — 2026-11-08

需求：演講者可在中、英、日之間切換，其他已選語言自動翻譯；選單指定顯示順序。另將雙向溝通頁原文與譯文區上下互換。

實作：演講自動模式預設開啟，預設三欄為繁中／英／日。Gemini 使用現有 Live Transcribe，languageCodes=[]；OpenAI 不傳來源語言提示，逐切段辨識。確定原文後並行啟動已選欄位翻譯；同語言也由文字模型判斷，避免一句夾雜多種語言時直接複製錯誤。保留數字、否定及醫療詞彙提示。各欄以 target 語言而非生成順序尋找既有譯文，字幕資料、匯出與摘要保留。自動模式不允許指定語言才可用的 Azure／Web Speech。雙向溝通僅調整 DOM 順序。

Google 官方文件確認省略 language_codes 或 [] 可跨語句動態偵測，支援 multilingual/code-switching：https://ai.google.dev/gemini-api/docs/live-api/live-transcribe#automatic-language-detection 。這不是帳戶權限或現場精準度驗證。

自檢（僅自審）：
1. 需求對照：已新增輪流發言自動辨識及各欄獨立翻譯；使用者選單控制顯示語言與順序；雙向溝通譯文在上、原文在下。
2. 驗證：88 項回歸測試通過，測試涵蓋第一欄延遲／失敗不阻擋其他欄、STT 完成即分派其他欄、語言切換維持順序、只開一條 Gemini 轉寫串流、正常與演講模式依語言重排串流內容。實際瀏覽器示範資料確認日／中／英重排及雙向區塊位置；未呼叫真實付費音訊 API。
3. 風險：各語言翻譯仍有延遲及額外文字 API 使用量；短語、混合語言及重疊發言可能誤辨識，不宣稱零延遲或辨識說話者身分。若服務未回傳來源語言標記，不會自行捏造精確語言識別結果。
4. 一致性：本機與靜態版提示、翻譯規則、演講模式、普通逐字稿、示範及文件同步；Azure、OpenAI、Gemini 金鑰不寫入 Git。
5. 使用方式：使用者只需選第 1／2／3 欄語言後開始聆聽；取消自動模式可恢復指定來源語言。雙向溝通畫面重新整理即可看到位置互換。

還能怎麼優化：值得以現場短錄音驗證中英日輪流發言的斷句、數字及醫療術語；本次沒有有效金鑰或錄音，未把模擬測試當作實際辨識品質證明。
