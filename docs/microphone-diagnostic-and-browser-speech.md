# 收音來源排查與 Chrome 辨識對照（2026-11-09）

問題：使用者回報 Gemini 收音辨識持續錯誤。僅憑轉寫文字無法確定是實際收音裝置、音質或辨識服務的原因。

增加明確的麥克風裝置選擇，授權後顯示實際音訊軌道名稱。PCM 收音使用選取裝置；Chrome Web Speech 自行使用瀏覽器預設裝置，故該模式停用自訂麥克風選單以免誤導。

將既有 native 引擎重新標示為「Chrome 語音辨識＋AI 文字翻譯（可用 Gemini）」，為其暫定辨識接上並行翻譯，final 取消暫定請求並送正式翻譯。停止及舊辨識器事件會受到取消保護，不應覆寫新字幕。Chrome 的語音服務負責辨識，文字交由所選 Gemini／OpenAI 服務翻譯，並非本機離線辨識。

## 自檢（僅自審）

1. 需求：辨認實際麥克風，提供獨立辨識服務作對照，避免只能沿用錯誤的 Gemini 原文。
2. 驗證：99 項回歸測試與建置通過。新增 1kHz 正弦波測試確認 44.1/48kHz 轉 16kHz 保留頻率及振幅；Chrome 中文暫定轉寫會立即排入翻譯，過期辨識器事件忽略。未錄製實際使用者音訊，未驗證實際辨識品質。
3. 風險：Chrome 語音辨識有瀏覽器與網路服務限制，不能保證較準；暫定文字翻譯增加 API 用量。麥克風選錯仍會造成錯誤。
4. 一致性：控制項與來源說明同步，僅改原版；西班牙語獨立副本未改。前端更新不需要重啟本機後端。
5. 使用：停止並重新整理；先選正確收音裝置。Gemini 仍錯時，選 Chrome 語音辨識、講者中文、文字翻譯服務 Gemini，用同一句中文比較原文。

官方 Gemini 音訊格式及中文辨識代碼已核對：https://ai.google.dev/gemini-api/docs/live-api/live-transcribe 。排查不應只靠換 prompt 或把外語輸出強制標為中文。

後續值得實際對照同一句話的兩種辨識結果，再決定主要辨識服務。
