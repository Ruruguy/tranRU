# 演講收音到字幕進度（2026-11-09）

新增可見流程列，區分瀏覽器收到音訊、音訊傳送請求成功、辨識文字回傳、文字翻譯回傳。音訊計數來自 Gemini 客戶端成功完成傳送請求後的 audio-sent 事件，不以音量條或排入佇列冒充成功；這不是 Gemini 已完成辨識的保證。

偵測到音量但 12 秒尚無辨識結果時，提示檢查裝置或切換辨識引擎。Chrome 及 Azure 模式會顯示各自辨識來源，不用 Gemini 的傳送計數判定它們失敗。追蹤不會改寫字幕、丟棄音訊或額外發出付費 API 請求。

## 自檢（僅自審）

1. 需求：使用者看到收音但無字幕，需要區分卡在音訊、辨識或翻譯；未將診斷顯示宣稱為辨識品質已修復。
2. 驗證：101 項測試及建置通過，含音訊傳送成功後才回報、四階段計數、各語言字幕隔離。已讀取使用者實際 Chrome 頁面，當時為雙向對話收音、演講停止，且尚未載入新增麥克風選單的發布版。未操作使用者麥克風或額外啟動 API。
3. 風險：無法從測試推定實際麥克風品質、網路可用性或服務辨識準確率；暫定辨識回傳字數可含修訂，不代表唯一逐字稿長度。
4. 一致性：客戶端事件、畫面流程列與單元測試同步；原版線上與本機前端同步，獨立西班牙語版未改。
5. 使用：先停止目前聆聽，再強制重新整理。確認有收音麥克風與流程列，再開始演講。仍不出字時回報流程列數字及狀態，勿貼金鑰。

後續需根據實際流程列與一句固定中文的測試結果決定下一步，避免盲目更換模型或調整 prompt。
